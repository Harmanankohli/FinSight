# Sentiment Analysis Review Plan — Market Context Agent

## Scope
Review all sentiment analysis code in the Market Context Agent (rebranded from "Sentiment Intelligence Agent" in Phase 3). Focus on correctness, completeness, potential issues, and alignment between VADER scoring layer and the CrewAI market context agent.

---

## Architecture Overview

The sentiment pipeline has **two distinct layers**:

| Layer | Location | Purpose |
|-------|----------|---------|
| **VADER News Sentiment** | `mcp_servers/tools/sentiment.py` + `mcp_servers/infra/news_fetch.py` | Fetches news from RSS/YF/DDG, scores headlines with VADER, returns structured sentiment data |
| **Market Context Agent** | `agent_4_crewai/executor.py` + `crew.py` | CrewAI agent performing macro regime + peer positioning analysis (no VADER involvement) |

**Key observation**: The Market Context Agent does NOT use VADER sentiment scores directly. It consumes macro indicators and peer financials. The VADER scoring layer is a separate MCP tool consumed by the orchestrator, not by the market context agent itself.

## Summary of Findings

### Architecture
- VADER scoring is cleanly separated from the Market Context Agent
- The agent name "Market Context" is a legacy artifact — no actual news sentiment is used by this agent
- `SentimentIntelligence` model may be out of sync with agent output fields

### Code Quality
- VADER singleton is correctly instantiated at module level in `sentiment.py`
- `news_fetch.py` creates new `SentimentIntensityAnalyzer()` instances per function call (minor inefficiency)
- Keyword matching logic is well-designed with bigram and split-at-2 variants

### Potential Issues
1. **Model mismatch**: `SentimentIntelligence` model fields (`social_sentiment_score`, `analyst_consensus`) don't match what Market Context Agent produces (`macro_regime`, `peer_comparison`)
2. **Duplicate VADER instances**: `news_fetch.py` creates new analyzer instances instead of reusing the singleton
3. **User-Agent spoofing**: YF news API uses browser User-Agent string
4. **No sentiment weighting**: Title and summary weighted equally regardless of length

### Positive Findings
- Anti-hallucination warnings when no articles found (lines 198-211)
- Proper error handling and fallback chain (RSS → YF → DDG)
- Rate limiting and caching in place
- Good test coverage for extraction and model validation
