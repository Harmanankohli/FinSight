Implementation Plan

Report Export: PPTX & DOCX

Allow users to download investment briefs as professional PowerPoint or Word documents
Project: FinSight Multi-Agent Investment System Date: 2026-06-06 Status: Proposed

1. Context & Motivation

Users complete an investment analysis on the Research page and see the brief rendered inline as markdown. There is currently no way to export or share this analysis outside the browser. The user wants a "Download as Report" option that generates professional PPTX or DOCX files suitable for sharing with colleagues, clients, or archiving.

Constraint: All document generation must happen on the orchestrator backend (Python). The frontend only triggers the download and receives the binary file.

Current Brief Storage

Briefs are stored in the SQLite ticker_briefs table. The brief_json column contains one of two shapes:

Full InvestmentBrief

{
  "ticker": "NVDA",
  "final_recommendation": "BUY",
  "confidence_score": 0.82,
  "recommendation_rationale": "...",
  "rag_insights": { ... },
  "quant_metrics": { ... },
  "sentiment_intelligence": { ... },
  "disclaimer": "..."
}

Minimal Brief (most common)

{
  "response_text": "## Executive Summary\n
  NVIDIA presents a compelling ...\n
  ## Quantitative Analysis\n
  Sharpe: 1.45, Vol: 28% ..."
}

The generator must handle both shapes gracefully — extracting structured metrics when available, falling back to markdown section parsing for minimal briefs.

3. Implementation Steps

1 Add Dependencies — pyproject.toml

Add two new packages to the [project] dependencies list:

"python-pptx>=1.0.0",
"python-docx>=1.1.0",

Then run uv sync to install.

Why these libraries? Both are pure-Python, well-maintained, and produce native Office Open XML files. No external system dependencies (unlike WeasyPrint/reportlab for PDF). They support programmatic slide/paragraph construction with full styling control.

Both functions accept the raw brief_data dict (parsed from brief_json) plus metadata fields from the ticker_briefs row. They return a BytesIO buffer ready to stream as a response.

Content Extraction (shared helper)

def _extract_sections(brief_data: dict) -> ReportContent:
    """Parse brief_data into structured report sections.

    Returns a ReportContent dataclass with:
      - executive_summary: str
      - sections: list[Section]  (title + body pairs)
      - metrics: dict | None     (if structured InvestmentBrief)
      - risks: list[str]
      - catalysts: list[str]
      - disclaimer: str
    """

Structured brief path: Extract fields directly from the Pydantic model shape — rag_insights, quant_metrics, sentiment_intelligence, recommendation_rationale.

Minimal brief path: Split response_text on ## markdown headers. Each header becomes a section title; everything until the next header becomes the body. Strip markdown formatting (bold, links, bullets → plain text) for clean document rendering.

New Endpoints

MethodPathPurpose
GET /api/reports/{brief_id}/{format} Download report for a specific brief by its database ID. format is pptx or docx.

Implementation

import json
from io import BytesIO
from starlette.requests import Request
from starlette.responses import Response

from shared.report_generator import generate_pptx, generate_docx

CONTENT_TYPES = {
    "pptx": "application/vnd.openxmlformats-officedocument"
            ".presentationml.presentation",
    "docx": "application/vnd.openxmlformats-officedocument"
            ".wordprocessingml.document",
}
GENERATORS = {"pptx": generate_pptx, "docx": generate_docx}


async def report_by_id(request: Request) -> Response:
    brief_id = request.path_params["brief_id"]
    fmt = request.path_params["format"]
    if fmt not in GENERATORS:
        return JSONResponse({"error": "format must be pptx or docx"}, 400)

    # Fetch brief from DB
    conn = await get_db()
    cursor = await conn.execute(
        "SELECT ticker, recommendation, confidence, brief_json, "
        "analysis_date FROM ticker_briefs WHERE id = ?", (brief_id,)
    )
    row = await cursor.fetchone()
    if not row:
        return JSONResponse({"error": "Brief not found"}, 404)

    ticker, rec, conf, brief_json_str, analysis_date = row
    brief_data = json.loads(brief_json_str) if brief_json_str else {}

    buf = GENERATORS[fmt](brief_data, ticker, rec, conf, analysis_date or "")
    filename = f"FinSight_{ticker}_{analysis_date or 'report'}.{fmt}"

    return Response(
        content=buf.getvalue(),
        media_type=CONTENT_TYPES[fmt],
        headers={"Content-Disposition": f'attachment; filename="{filename}"'},
    )

4 Frontend — Research Page Download Bar — web/nextjs-app/app/research/page.tsx

Trigger Condition

Show the download bar when !running && hasMessages and the last assistant message contains a BUY/HOLD/SELL signal. This means the analysis is complete and a brief has been saved.

Ticker Extraction

Extract the ticker from the user's original query message using regex: /\b([A-Z]{1,5})\b/ matching common stock ticker patterns. The first all-caps 1-5 letter word that isn't a common English word (I, A, THE, etc.) is the ticker.

Download Logic

const downloadReport = async (ticker: string, format: "pptx" | "docx") => {
  const res = await fetch(
    `/api/orch/api/reports/ticker/${ticker}/latest/${format}`
  );
  if (!res.ok) return;  // show error toast
  const blob = await res.blob();
  const url = URL.createObjectURL(blob);
  const a = document.createElement("a");
  a.href = url;
  a.download = `FinSight_${ticker}_${new Date().toISOString().slice(0,10)}.${format}`;
  a.click();
  URL.revokeObjectURL(url);
};

4. Report Content Strategy

Section Mapping

The generator maps brief content into report sections. For structured briefs, it extracts fields directly. For minimal briefs, it parses markdown headers.

Report SectionStructured Brief SourceMinimal Brief Source
Executive Summary recommendation_rationale First paragraph or ## Executive Summary section
Key Metrics quant_metrics.* fields as a table Skip (no structured data)
Fundamental Analysis rag_insights (revenue growth, R&D, guidance) ## Fundamental or ## RAG section
Quantitative Analysis quant_metrics (Sharpe, vol, beta, VaR, DCF) ## Quant section
Market Sentiment sentiment_intelligence (consensus, targets, insider) ## Market or ## Sentiment section
Risks & Catalysts rag_insights.key_risks + sentiment.key_catalysts ## Risk section
Disclaimer disclaimer field Default disclaimer text

Markdown Stripping

The response_text contains markdown formatting. Before inserting into PPTX/DOCX, strip:

  • **bold** → apply bold formatting natively in the document
  • - bullet → convert to native bullet points
  • [link](url) → plain text (or hyperlink in DOCX)
  • | table | → native table (best-effort parsing)
  • Headers (##) → used as section delimiters, then stripped

6. Risks & Edge Cases

RiskMitigation
Brief has no response_text and no structured fields Fall back to a single-section report with the raw query field and "No analysis content available" body
Very long briefs exceed slide capacity Split sections longer than ~300 words across multiple slides with "(continued)" suffix
Markdown tables in response_text Best-effort parsing of pipe-delimited tables into native PPTX/DOCX tables; fall back to preformatted text
Special characters in ticker or content python-pptx/docx handle Unicode natively; sanitize filename with regex
Concurrent requests generating large files Generation is in-memory and fast (~50ms for typical briefs); no caching needed initially
