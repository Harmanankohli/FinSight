Architecture Improvements

Twelve targeted improvements to the current architecture, excluding the framework-proliferation topic (design intent). Ordered by category — each includes problem location, proposed change, and effort estimate.

Data & Connections

1. SQLite Connection Pooling

data Effort: small (~20 lines, 1 file)

Problem: shared/memory/store.py:84-96 — get_db() opens a brand-new aiosqlite connection on every call with no pooling. Every ticker lookup, portfolio read, filing-dedup check, and performance write creates + tears down a connection. SQLite serializes all writes even with WAL mode — under concurrent requests, busy_timeout=5000 causes 5-second stalls when writes queue up.

# Current: new connection per call
conn = await get_db()       # open
cursor = await conn.execute(...)
result = cursor.fetchone()
await conn.close()          # close

# Dozens of these per query across 5 services, all contending on the same .db file.

Proposed change: Use a single long-lived connection with an asyncio.Lock for writes, or add aiosqlite connection pooling (e.g., a pool of 2-3 connections with a context manager). Since aiosqlite has no built-in pool, the simplest approach is a module-level global connection, opened lazily, with explicit async with write_lock: around mutations.

# shared/memory/store.py — proposed:
import asyncio
from contextlib import asynccontextmanager

_db_conn = None
_db_lock = asyncio.Lock()

async def get_db(path=DB_PATH):
    global _db_conn
    if _db_conn is None:
        path.parent.mkdir(parents=True, exist_ok=True)
        _db_conn = await aiosqlite.connect(str(path))
        await _db_conn.execute("PRAGMA journal_mode=WAL")
        await _db_conn.execute("PRAGMA foreign_keys=ON")
        await _db_conn.execute("PRAGMA busy_timeout=5000")
        await init_db(_db_conn)
    return _db_conn

# Callers that write must acquire the lock:
async with _db_lock:
    conn = await get_db()
    await conn.execute("INSERT ...")

Files to touch: shared/memory/store.py, shared/memory/ticker_memory.py, shared/memory/portfolio_store.py, shared/memory/performance_tracker.py, shared/memory/memory_service.py — remove await conn.close() from all callers.

2. MCP Client as Long-Lived Singleton

data Effort: medium (~50 lines across 4 files)

Problem: Every sub-agent creates its own MCPClient instance, calls connect_all(), does work, then calls disconnect_all() — per request. The orchestrator does the same in agent_executor.py:146-179 just for ticker validation. MCP connections use SSE (Server-Sent Events), which is long-polling — each connect involves an HTTP upgrade handshake taking ~100-500ms. The connect/disconnect dance happens on every A2A request.

# Each agent executor:
async def _disconnect(self):
    if self._mcp is not None:
        await self._mcp.disconnect_all()
        self._mcp = None

# Called in finally block of every stream() — per user query.

Locations:

  • agent_2_llamaindex/executor.py:109-118
  • agent_3_langgraph/executor.py:32-37
  • agent_4_crewai/executor.py:36-45
  • agent_1_adk/agent_executor.py:146-179 (temporary MCP for ticker check)

Proposed change: Make MCPClient a module-level singleton in shared/mcp_client.py, initialized once at import with lazy connect on first tool call. Remove connect/disconnect from all per-request lifecycles.

# shared/mcp_client.py — proposed singleton:
_global_client = None
_client_lock = asyncio.Lock()

async def get_mcp_client() -> MCPClient:
    global _global_client
    if _global_client is None:
        async with _client_lock:
            if _global_client is None:
                _global_client = MCPClient(configs=[
                    MCPServerConfig(name="finsight-mcp", url=MCP_SERVER_URL)
                ])
                await _global_client.connect_all()
    return _global_client

# Remove _ensure_connected/_disconnect from all 4 agent executors.

3. Rate Limiting

data Effort: small (~40 lines, 1 file)

Problem: No rate limiting anywhere. 10 concurrent users → 10 simultaneous yfinance API calls + 10 SEC EDGAR requests. SEC EDGAR specifically rate-limits to ~10 requests/second with a hard ban for exceeding it. Yahoo Finance has undocumented rate limits that return HTTP 429 under load.

Hot paths with no throttling:

  • mcp_servers/finsight_server.py:272-280 — get_prices() calls yfinance
  • mcp_servers/finsight_server.py:475-490 — _fetch_submissions() calls SEC EDGAR with 3-attempt retry but no rate limiting between retries
  • mcp_servers/finsight_server.py:1152-1180 — _fetch_rss() fires all 3 RSS feeds without staggering

Proposed change: Add a token-bucket rate limiter to shared/ and wrap the SEC EDGAR client and RSS fetcher. The MCP server's _EdgarClient is the single point of contact — one limiter there protects all callers.

# shared/rate_limiter.py — proposed:
import asyncio
import time

class TokenBucket:
    def __init__(self, rate: float, burst: int):
        self.rate = rate
        self.burst = burst
        self.tokens = burst
        self.last = time.monotonic()
        self._lock = asyncio.Lock()

    async def acquire(self):
        async with self._lock:
            now = time.monotonic()
            self.tokens = min(self.burst, self.tokens + (now - self.last) * self.rate)
            self.last = now
            if self.tokens >= 1:
                self.tokens -= 1
                return
        # Wait for next token
        await asyncio.sleep(1.0 / self.rate)
        return await self.acquire()

# Usage in _EdgarClient:
_sec_limiter = TokenBucket(rate=8, burst=10)  # 8 req/s, burst 10

async def _fetch_submissions(self, cik, ticker):
    await _sec_limiter.acquire()
    ...

Security & Configuration

4. SEC EDGAR User-Agent Compliance

security Effort: trivial (~1 line)

Problem: mcp_servers/finsight_server.py:358 — the SEC EDGAR client sends:

_SEC_HEADERS = {
    "User-Agent": "FinSight Research (contact@finsight.com)",
    ...
}

contact@finsight.com is not a resolving domain. SEC EDGAR robots.txt explicitly requires a valid User-Agent with contact information. If SEC reviews the traffic source and the domain doesn't resolve, they may block the IP address entirely. This is not theoretical — SEC actively enforces this for high-volume crawlers.

Proposed change: Replace with a real contact email address or a documented dev-mode placeholder that warns when used.

# Option A: real contact
"User-Agent": "FinSight Research (your.name@yourdomain.com)"

# Option B: env var with warning
import os
_user_agent = os.environ.get(
    "SEC_USER_AGENT",
    "FinSight Research (dev-mode — set SEC_USER_AGENT env var for production)"
)
if "dev-mode" in _user_agent:
    logger.warning("SEC User-Agent is dev-mode placeholder — may be blocked")
_SEC_HEADERS = {"User-Agent": _user_agent}

5. Hardcoded api_key="lmstudio"

security Effort: trivial (~4 files, 1 line each)

Problem: api_key="lmstudio" is hardcoded in 4 files. While LM Studio doesn't validate API keys, these strings are:

  • A maintenance hazard when switching to a real provider (OpenAI, Anthropic, etc.)
  • Present in DEBUG-level logs (no sanitizer currently exists)
  • Copied into source control — a real API key would be a leak

Locations:

  • agent_1_adk/agent.py:21
  • agent_2_llamaindex/index_manager.py:28
  • agent_4_crewai/crew.py:15
  • agent_3_langgraph/nodes.py (likely similar pattern)

Proposed change: Read from shared/config.py as LLM_API_KEY env var, defaulting to "lmstudio" for backward compatibility.

# shared/config.py — add:
LLM_API_KEY = os.environ.get("LLM_API_KEY", "lmstudio")

# Every agent reads:
from shared.config import LLM_API_KEY
# then: api_key=LLM_API_KEY

6. Hardcoded HF_HUB_OFFLINE=1

security Effort: small (~5 lines, 1 file)

Problem: shared/config.py:28 forces HuggingFace Hub offline mode:

os.environ.setdefault("HF_HUB_OFFLINE", "1")

If any embedding model (all-MiniLM-L6-v2, cross-encoder/ms-marco-MiniLM-L-6-v2) isn't cached locally, the system fails silently — SentenceTransformer raises a connection error, caught somewhere as logger.warning, and the agent returns a degraded response (no RAG, no semantic cache, no agent registry search). Fine for a stable dev environment. Breaks on first deploy to a fresh machine.

Proposed change: Keep the offline default but add a startup check that warns if required models are missing from local cache, with instructions to pre-download or set HF_HUB_OFFLINE=0.

# shared/config.py — proposed addition:
_MODEL_CHECKED = False

def check_embedding_models():
    global _MODEL_CHECKED
    if _MODEL_CHECKED:
        return
    _MODEL_CHECKED = True
    from pathlib import Path
    import os
    cache_dir = Path.home() / ".cache" / "huggingface" / "hub"
    model_ids = [
        f"sentence-transformers/{EMBED_MODEL}",
        f"cross-encoder/{RERANKER_MODEL.split('/')[-1]}",
    ]
    for mid in model_ids:
        # Snapshot folder pattern: models--sentence-transformers--all-MiniLM-L6-v2
        safe = mid.replace("/", "--")
        model_path = cache_dir / f"models--{safe}"
        if not model_path.exists():
            logger.warning(
                "Embedding model '%s' not found in HF cache (%s). "
                "Set HF_HUB_OFFLINE=0 in .env to auto-download, or run: "
                "python -c \"from sentence_transformers import SentenceTransformer; "
                "SentenceTransformer('%s')\"",
                mid, model_path, mid,
            )

7. Duplicated Ticker Validation Logic

code Effort: medium (~80 lines removed, ~20 added to shared/)

Problem: The pattern of _validate_ticker(), _resolve_ticker(), and _disconnect() is copy-pasted across all 4 agent executors with near-identical implementation. Any bug fix or improvement must be applied 4 times.

Locations:

  • agent_2_llamaindex/executor.py:131-149 — _validate_ticker, _resolve_ticker, _disconnect
  • agent_3_langgraph/executor.py:67-83 — same 3 methods
  • agent_4_crewai/executor.py:88-104 — same 3 methods
  • agent_1_adk/agent_executor.py — inline ticker check via temporary MCP (lines 144-179)
# Each agent has this duplicated:
async def _validate_ticker(self, ticker):
    if not ticker: return False, "", "..."
    try:
        await self._ensure_connected()
        return await validate_ticker_via_mcp(self._mcp, ticker)
    except:
        return True, ticker, ""

async def _resolve_ticker(self, query, exclude_ticker=""):
    try:
        await self._ensure_connected()
        return await resolve_ticker_via_mcp(self._mcp, query, exclude_ticker)
    except:
        return "", ""

Proposed change: Move to shared/ticker_utils.py which already contains validate_ticker_via_mcp() and resolve_ticker_via_mcp(). Add convenience wrappers that handle MCP client lifecycle internally (connect-once, reuse). All agents call one function.

# shared/ticker_utils.py — proposed additions:
async def validate_ticker(ticker: str) -> tuple[bool, str, str]:
    """Validate ticker against SEC. Manages MCP lifecycle internally."""
    mcp = await _get_shared_mcp()
    return await validate_ticker_via_mcp(mcp, ticker)

async def resolve_ticker(query: str, exclude: str = "") -> tuple[str, str]:
    """Resolve company name to ticker. Manages MCP lifecycle internally."""
    mcp = await _get_shared_mcp()
    return await resolve_ticker_via_mcp(mcp, query, exclude)

8. Inconsistent Error Propagation

code Effort: medium (across 5+ files)

Problem: The same failure travels through three different error formats depending on which layer catches it:

LayerError FormatExample
MCP tools{"error": str} in result dict{"ticker":"XXX","error":"Tool failed: ...","data":[]}
GenericAgentExecutorTaskState.FAILED + text messageA2A TaskStatusUpdateEvent with state=FAILED
SubAgentClient{"error": str} JSON string'{"error": "Agent failed: ..."}'
Orchestrator executorMixed — text or error keySometimes TaskState.FAILED, sometimes text

An A2A tool failure at the MCP level is wrapped in a dict, serialized to JSON, sent over SSE, parsed by the agent, re-wrapped in an A2A artifact, serialized to protobuf, sent over HTTP, parsed by SubAgentClient, re-serialized as JSON string, returned to the LLM as a function result, and finally the LLM decides how to surface it. Each hop changes the shape.

Proposed change: Standardize on a single error envelope class in shared/models.py that all layers produce. The A2A layer is the boundary — errors crossing it should use a consistent schema.

# shared/models.py — proposed addition:
from dataclasses import dataclass

@dataclass
class AgentError:
    """Standard error envelope across all FinSight services."""
    code: str          # "MCP_TIMEOUT", "INVALID_TICKER", "AGENT_UNAVAILABLE"
    message: str       # Human-readable description
    detail: dict | None = None  # Optional structured context

    def to_dict(self) -> dict:
        return {"error": self.code, "message": self.message,
                "detail": self.detail or {}}

    @staticmethod
    def from_a2a(task) -> "AgentError":
        """Parse A2A terminal state into AgentError."""
        ...

Scope is medium because it touches every error-return path. Best done as a dedicated refactor pass, not mixed with feature work.

9. Import-Time Side Effects (OpenTelemetry)

code Effort: small (~5 lines per file)

Problem: OpenTelemetry instrumentors fire at module import time in multiple files:

  • agent_1_adk/sub_agent_client.py:12 — HTTPXClientInstrumentor().instrument()
  • agent_2_llamaindex/server.py:26-29 — LlamaIndexInstrumentor().instrument() + StarletteInstrumentor().instrument()
  • agent_3_langgraph/server.py:24-32 — StarletteInstrumentor + LangChainInstrumentor
  • agent_4_crewai/server.py:24-26 — CrewAIInstrumentor + StarletteInstrumentor

This means importing any symbol from agent_1_adk.sub_agent_client globally instruments all httpx clients — even in unit tests or scripts that just need the data model. Breaks test isolation and creates non-deterministic failures when import order changes.

Proposed change: Move instrumentor calls from module level into a lazy init_instrumentation() function called from the server entry point, not at import.

# shared/observability.py — proposed additions:
def init_instrumentation(agent_type: str) -> None:
    """One-time initialization of agent-specific OpenTelemetry instrumentors."""
    if agent_type == "orchestrator":
        HTTPXClientInstrumentor().instrument()
    elif agent_type == "rag":
        LlamaIndexInstrumentor().instrument()
        StarletteInstrumentor().instrument()
    ...

# Called from server.py entry point, not at import:
def main():
    init_instrumentation("orchestrator")
    uvicorn.run(...)

10. Redundant Memory Persistence Paths

code Effort: medium (~40 lines removed)

Problem: The same conversation events are written to memory three ways on every analysis turn:

PathLocationWhat it does
1. after_agent_callbackagents/finsight_agent/agent.py:202-216callback_context.add_events_to_memory()
2. Executor fallbackagent_1_adk/agent_executor.py:253-257_add_events_to_memory() — get_session → add_session_to_memory()
3. Direct persistagent_1_adk/agent_executor.py:507-530_persist_to_memory() — add_events_to_memory directly

Paths 2 and 3 were added as reliability fixes when the callback path was unreliable. Now all three fire on every turn. This triples write load on SQLite and makes the memory layer harder to reason about — which path actually controls what gets stored?

Proposed change: Consolidate to a single path. The after_agent_callback is the canonical path for ADK Web UI mode. The executor paths (2, 3) should only fire when the standalone A2A server (agent_1_adk/main.py) is started directly — and should be gated by a flag.

Reliability

11. Cancellation

reliability Effort: medium (~60 lines across 2 files)

Problem: Both agent executors raise NotImplementedError on cancel:

  • shared/generic_executor.py:133-137 — GenericAgentExecutor.cancel() raises Exception("cancel not supported")
  • agent_1_adk/agent_executor.py:360-361 — FinSightAgentExecutor.cancel() raises NotImplementedError

Once a request is submitted, it cannot be aborted. If a sub-agent hangs, the entire pipeline blocks for the full A2A_TIMEOUT (180 seconds). The orchestrator has no per-agent timeout — one slow agent delays the entire response. This is the single biggest reliability gap for production use.

Proposed change:

11a. GenericAgentExecutor.cancel() — Store the asyncio.Task running the agent's stream() iteration. On cancel, task.cancel() + emit TASK_STATE_CANCELED event.

# shared/generic_executor.py — proposed:
class GenericAgentExecutor(AgentExecutor):
    def __init__(self, agent: BaseAgent):
        self.agent = agent
        self._task: asyncio.Task | None = None

    async def execute(self, context, event_queue):
        self._task = asyncio.current_task()
        ...

    async def cancel(self, context, event_queue):
        if self._task and not self._task.done():
            self._task.cancel()
            await event_queue.enqueue_event(TaskStatusUpdateEvent(
                task_id=...,
                context_id=...,
                status=TaskStatus(state=TaskState.TASK_STATE_CANCELED),
            ))

11b. FinSightAgentExecutor.cancel() — ADK's Runner.run_async() doesn't expose a public cancel method. The executor stores the running asyncio.Task and calls cancel() on it, which propagates through the ADK event loop.

# agent_1_adk/agent_executor.py — proposed:
class FinSightAgentExecutor(AgentExecutor):
    def __init__(self, runner: Runner):
        self._runner = runner
        self._task: asyncio.Task | None = None

    async def execute(self, context, event_queue):
        self._task = asyncio.current_task()
        ...

    async def cancel(self, context, event_queue):
        if self._task and not self._task.done():
            self._task.cancel()
            await event_queue.enqueue_event(TaskStatusUpdateEvent(
                task_id=...,
                context_id=...,
                status=TaskStatus(state=TaskState.TASK_STATE_CANCELED),
            ))

11c. Per-agent timeout in SubAgentClient — sub_agent_client.py:234 wraps the A2A client.send_message() in asyncio.wait_for() with the existing A2A_TIMEOUT, but currently applies the global timeout to all agents combined. Split into per-agent timeout so one slow agent doesn't kill the others.

12. InMemoryTaskStore

reliability Effort: small (documentation only — known limitation)

Problem: Every agent server uses InMemoryTaskStore():

  • agent_1_adk/main.py:75
  • agent_2_llamaindex/server.py:85
  • agent_3_langgraph/server.py:78
  • agent_4_crewai/server.py:74

A2A tasks in-flight during a server restart are lost. The orchestrator receives no error — the sub-agent simply becomes unreachable, and the LLM gets back {"error": "Agent failed: ..."} or a timeout. For a research system this is acceptable; for production it means lost work.

Proposed change: Replace InMemoryTaskStore with the same DatabaseSessionService pattern used for the orchestrator (SQLite-backed). Each sub-agent gets its own task_store.db. Effort is small per agent but requires adding aiosqlite and a simple tasks table — same pattern as shared/memory/store.py.

# shared/store.py — proposed addition:
from a2a.server.tasks import TaskStore

class SQLiteTaskStore(TaskStore):
    """A2A TaskStore backed by SQLite for persistence across restarts."""
    ...

Priority: Low. Document as a known limitation with a note to address before production deployment.
