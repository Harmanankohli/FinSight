Codebase Navigation Guide

A recommended sequence for reading the FinSight codebase, from first-principles infrastructure to the full request lifecycle. Each step explains what to read, what you'll learn, and how it connects to the next.

Reading Sequence

Start at Step 0 and proceed in order. Each step is ~15-30 minutes of focused reading. By the end you will understand the full data flow from a user query like "Should I invest in NVDA?" through all six agents to a final BUY/HOLD/SELL verdict.

Step 0 — Project Layout & Configuration

primer src/ • pyproject.toml • .env.example • README.md

What to read:

  • README.md — architecture diagram, project structure tree, key features, tech stack table, quick-start instructions
  • pyproject.toml — optional dependency groups that define each agent's framework (orchestrator/rag/quant/analytics/reviewer/market/mcp_server)
  • .env.example — every env var the system reads (ADK_MODEL, AGENT_SEED_URLS, LLM_BASE_URL, MCP_SERVER_URL, etc.)

What you learn: The system's shape — 6 Python agents + 1 web frontend + 1 MCP tool server. Each agent uses a different AI framework (ADK, LlamaIndex, LangGraph, CrewAI, PydanticAI, OpenAI Agents SDK). All communicate via A2A JSON-RPC over HTTP. LM Studio provides local LLM inference.

Step 1 — Shared Library Foundation

infrastructure src/shared/

What to read (in order):

  1. settings.py — pydantic-settings Settings class. Every agent imports get_settings() for ports, model names, timeouts. This is the source of truth for all configuration.
  2. bootstrap.py — bootstrap(service_name) called by every agent at startup. Sets up logging, Langfuse instrumentation, event loop policy, HF_HUB_OFFLINE. The first import every agent makes.
  3. agent_server.py — build_agent_app(). All 5 sub-agents use this Starlette factory to get A2A routes (/card, /a2a, /health, /release-evals) plus AuthMiddleware, Langfuse, file logging. Saves ~100 lines of boilerplate per agent.
  4. base_agent.py — BaseAgent ABC with stream() lifecycle. All 5 sub-agent implementations extend this.
  5. generic_executor.py — GenericAgentExecutor wraps BaseAgent.stream() into A2A TaskArtifactUpdateEvent / TaskTerminalEvent lifecycle. This is the bridge between agent logic and the A2A protocol.
  6. agent_models.py — All Pydantic output schemas (QuantAgentOutput, MarketContextOutput, RAGAgentOutput, AnalyticsAgentOutput, ReviewerAgentOutput, InvestmentBrief). Typed boundaries between every agent.
  7. mcp_client.py — get_shared_mcp() singleton. Every agent calls MCP data tools through this single process-wide SSE connection.
  8. ticker_utils.py — extract_ticker(), resolve_and_validate_ticker(), extract_holdings(). Shared across all 6 agents.
  9. logging_config.py — @logged/@logged_sync decorators with ANSI colored output, service badges, latency_ms.
  10. metrics.py — MetricValue float subclass with validation metadata + computation functions (Sharpe, Beta, Sortino, RSI). Used by Quant and Analytics.

What you learn: The shared layer that every agent depends on. Understand build_agent_app() + GenericAgentExecutor + BaseAgent first because every sub-agent follows the same pattern: BaseAgent.stream() → yields dict → GenericAgentExecutor converts to A2A events. Without this foundation, agent code looks like disconnected magic.

Step 2 — Memory & Caching Infrastructure

infrastructure src/shared/memory/ • src/shared/semantic_cache.py • src/shared/ttl_cache.py • src/shared/llm_queue.py • src/shared/eval_gate.py

What to read:

  1. memory/store.py — SQLiteMemoryService. The SQLite schema: ticker_briefs, user_profiles, recommendations, eval_results, agent_outputs, audit_log tables.
  2. memory/ticker_memory.py — TickerMemory. get_latest() is the key method — the orchestrator checks it on every query to short-circuit if today's brief already exists.
  3. memory/agent_output_store.py — Cross-process SQLite store shared between orchestrator (store_agent_output) and reviewer (get_agent_outputs).
  4. ttl_cache.py — TTLCache used by MCP server for all data caches (1m prices, 1h financials, permanent filings, etc.)
  5. semantic_cache.py — SemanticCache. ChromaDB-based embedding similarity. Date-scoped (same query different day = miss). Controlled by SEMANTIC_CACHE_ENABLED.
  6. llm_queue.py — LLMPriorityQueue. 3-tier async semaphore: CRITICAL (production), NORMAL (warmup), LOW (eval). Prevents eval from starving production inference.
  7. eval_gate.py — defer_eval()/release_evals(). Cross-process coordination: sub-agents defer eval LLM calls until orchestrator POSTs /release-evals.

What you learn: How the system avoids unnecessary work. Four caching layers (MCP TTL cache, LangChain SQLiteCache, ChromaDB semantic cache, per-query memory short-circuit). The LLM priority queue prevents LM Studio saturation. Deferred eval prevents 5 agents competing with synthesis for LLM slots.

Step 3 — MCP Data Server

data layer src/mcp_tools/

What to read:

  1. _app.py — FastMCP("finsight-mcp") composition root. Exposes all data tools via SSE on port 8010 (legacy 8007).
  2. tools/market_data.py — get_prices(), get_financials(), get_options_chain(), get_macro_indicators(). Each function wrapped with @cache_result decorator pointing to the TTL cache dicts.
  3. tools/edgar.py — get_financial_filings(), get_filing_content(), full_text_search(). SEC EDGAR access with CIK resolution.
  4. tools/ticker.py — validate_ticker(), resolve_company_ticker(). Used by ticker_utils.py.
  5. tools/sentiment.py — get_news_sentiment(), get_analyst_activity(), get_earnings_history().
  6. tools/agent_registry.py — find_agent() with sentence-embedding search over agent_cards/. Not used in main flow but interesting.
  7. infra/rate_limiters.py — TokenBucket rate limiters for yfinance and yahooquery.
  8. infra/embed.py — Lazy sentence-transformers loader (loaded on first call, not at import).

What you learn: Every data source in the system. All agents funnel through this single MCP server for prices, financials, news, filings, macro data, peers, insider transactions, analyst activity. The tool functions are thin wrappers around yfinance/yahooquery with caching and rate limiting. No agent fetches external data directly.

Step 4 — Orchestrator (Entry Point & Coordination)

control plane src/orchestrator/

What to read (in order):

  1. main.py — Starlette app entry point. Lifespan runs SubAgentClient.discover() in background. Routes: /api/, /card, /a2a. Note: run_adk_web.bat uses ADK web UI mode instead, which bypasses this file and uses web/agent.py.
  2. agent.py — root_agent ADK LlmAgent with tools send_message and load_memory. The _build_instruction() generates the system prompt dynamically (callable instruction). _AGENT_TASK_TEMPLATES defines per-agent task content. _STATIC_PREAMBLE instructs the LLM to emit all send_message calls in one turn for parallel execution.
  3. agent_executor.py — FinSightAgentExecutor.execute(). The main request handler. Sequence: guardrails → semantic cache → memory context → Runner.run_async() → LLM delegates to sub-agents → collect responses → output guardrails → auto-save → eval.
  4. sub_agent_client.py — SubAgentClient. A2A HTTP client. send_message() with SendMessageInput(agent_name, ticker) Pydantic model. Per-agent timeouts via asyncio.wait_for. Trace context injection.
  5. services.py — get_memory_service(), get_task_service() factories.
  6. web/agent.py — ADK Web UI callback layer. _memory_cache_callback (before_agent — short-circuits if today's brief exists). _persist_memory_callback (after_agent — saves brief, fires RAGAS eval). _is_analysis_turn() gates persist+eval to avoid memory pollution on non-analysis turns.
  7. agui_bridge.py — AG-UI SSE bridge for CopilotKit frontend. stream_events endpoint, delegate_all_agents().
  8. api_routes.py — REST API: POST /api/query, GET /api/memory, research endpoints.
  9. auth_routes.py — Login, logout, token refresh.

What you learn: The complete request lifecycle. How a user query enters the system (frontend → AG-UI bridge / REST API / ADK web), flows through guardrails and caching, gets delegated to 5 sub-agents in parallel via A2A, and how results are synthesized into a final BUY/HOLD/SELL with auto-save and eval. Pay special attention to agent_executor.py, which is the single most important file in the codebase.

Step 5 — Quant Agent (LangGraph)

agent src/quant/

What to read (in order):

  1. server.py — QuantAgent(ServerBaseAgent). Minimal — just creates the agent card and calls build_agent_app().
  2. executor.py — QuantAgent.stream(). Extracts holdings, calls analyze() which runs graph.run(). This is where get_shared_mcp() is passed into the LangGraph state.
  3. state.py — QuantAnalysisState(TypedDict) with Annotated reducers (_merge_dict, _last_str, _last_nonnull). Critical for understanding LangGraph fan-in.
  4. graph.py — 6-node DAG topology. START fans out to 5 parallel nodes, fans in at format_output → llm_summary.
  5. nodes/data_fetch.py — 7 data-fetching nodes: prices, fundamentals, options flow, insider signals, analyst positioning, web context. All call MCP tools through the shared client in state.
  6. nodes/calculations.py — _run_monte_carlo(), _score_*() functions (8 groups), _weighted_vote() → BUY/HOLD/SELL. This is the core quant logic.
  7. nodes/dcf.py — dcf_valuation_node. 5-year tapered DCF with CAPM WACC, multi-scenario, sensitivity matrix. Routes banks to P/B valuation.
  8. nodes/technical.py — compute_metrics_node (Sharpe, Beta, VaR, etc.) and technical_analysis_node (RSI, MACD, Bollinger, trends).
  9. nodes/monte_carlo.py — stress_test_node. Beta-adjusted crash scenarios + GBM Monte Carlo with sector-aware shock data.
  10. nodes/summary.py — format_output_node (weighted voting) and llm_summary_node (LLM generation, CRITICAL priority, data-readiness guard).
  11. nodes/portfolio.py — correlation_node. Only fires when portfolio holdings provided.

What you learn: The most computationally intensive agent. The LangGraph fan-in topology is the trickiest part — the state reducers handle concurrent writes from parallel nodes. The volatility gate (dcf_valuation vs stress_test) is a key routing decision. The 8-group weighted voting is the final signal computation.

Step 6 — RAG Agent (LlamaIndex)

agent src/financial_rag/

What to read:

  1. server.py — Minimal server. Includes _do_prewarm() startup warm-up.
  2. executor.py — RAGAgent.stream(). Ticker extraction, fires background ingestion tasks (_ensure_ingested, _ensure_news_ingested), then FinancialIndexManager.query() returns results immediately from already-indexed data.
  3. index_manager.py — FinancialIndexManager. 3 ChromaDB collections (sec_filings, news, earnings). Query intent classification routes to the right collection. Incremental ingestion tracks ingested URLs in SQLite.
  4. hybrid_search.py — BM25 + dense embedding + RRF fusion + CrossEncoder reranking.
  5. document_ingestion.py — Ingestion pipeline from SEC filings + web content.

What you learn: The simplest agent. Key design: ingestion is fire-and-forget, queries return from already-indexed data. Incremental ingestion means restarts never re-index. The multi-collection query intent routing is the main architectural decision.

Step 7 — Market Context Agent (CrewAI)

agent src/market_context/

What to read:

  1. server.py — Minimal server.
  2. executor.py — MarketContextAgent.stream(). 3-step parallel data collection: macro + financials → peer resolution → peer financials + prices.
  3. crew.py — MarketContextCrew. Single Analyst crew (not multi-agent). Pre-collected data injected into task context. Outputs JSON via MarketContextOutput Pydantic model.
  4. mcp_tools.py — DynamicMCPTool wrapping MCP tools as CrewAI BaseTool.

What you learn: The simplest CrewAI agent — single-agent crew with pre-collected data. The data collection pipeline is the interesting part: 3 sequential steps with parallel fetches within each step. This agent owns macro regime analysis and peer landscape positioning exclusively.

Step 8 — Analytics Agent (PydanticAI)

agent src/analytics/

What to read (in order):

  1. server.py — Minimal server.
  2. executor.py — AnalyticsAgent.stream(). Runs AnalyticsPipeline.run() through the PydanticAI graph.
  3. state.py — AnalyticsState dataclass. Unlike Quant (TypedDict + reducers), PydanticAI uses mutable dataclass carried through the graph.
  4. deps.py — AnalyticsDeps carrying ticker, period, mcp_client.
  5. graph.py — 4-node sequential DAG using BaseNode / End pattern.
  6. nodes/ — 6 analysis modules: data_fetch, trend (SMA/MACD/RSI), forecast (Holt-Winters), charts, statistics (skew/kurtosis/JB-test), anomaly (z-score spikes), summary (signal + LLM).

What you learn: The most straightforward agent pipeline — 4 sequential nodes. PydanticAI's BaseNode pattern is simpler than LangGraph. The analytics signal is purely statistical (trend direction, forecast change, anomaly severity, distribution shape). No LLM until the very end (summary node).

Step 9 — Reviewer Agent (OpenAI Agents SDK)

agent src/reviewer/

What to read (in order):

  1. server.py — Minimal server.
  2. executor.py — ReviewerAgent.stream(). 6 deterministic Python checks run first, then a single LLM call synthesizes the structured review.
  3. agent.py — reviewer_agent OpenAI Agents SDK Agent with 6 tool functions.
  4. tools/ package (6 files):
    • contradiction.py — 14 cross-agent signal conflict checks
    • confidence.py — Per-agent confidence derivation + meta-confidence weighting
    • validation.py — Recommendation validation against data support
    • verification.py — DCF math verification, source presence checks
    • consistency_checker.py — RSI extremes, DCF vs MC divergence
    • dcf_validator.py — Intrinsic/market ratio, WACC range, growth sanity
  5. guardrails.py — Input guardrail for JSON payload validation.

What you learn: Design principle: deterministic tools first, LLM once. All 6 validation checks are pure Python (no LLM calls). The LLM receives pre-computed results and produces a structured ReviewerAgentOutput with verdict, confidence breakdown, contradictions, flags. This is the final quality gate before the recommendation reaches the user.

Step 10 — Report Generator

output src/shared/reports/ • src/shared/templates/

What to read:

  1. src/shared/reports/ package — deck_model.py, html_renderer.py (Jinja2 + Chart.js), playwright_export.py (A4 PDF), extraction/ (brief-to-deck model extraction).
  2. src/shared/templates/ — Jinja2 HTML templates with Chart.js interactive charts.

What you learn: How investment briefs become self-contained HTML reports and PDFs. The extraction pipeline pulls data from the stored InvestmentBrief and constructs a structured deck model, then renders via Jinja2 templates with Chart.js visualizations (forecast distribution, Monte Carlo, trend overlays, stress scenarios, DCF breakdown, anomaly alerts).

Step 12 — Tests & Evaluation

quality src/tests/ • src/shared/runtime_eval.py

What to read:

  1. src/tests/ structure — unit/, integration/, regression/, characterization/, security/, evaluation/
  2. docs/TESTS.md — Test coverage, patterns, RAGAS evaluation, running instructions
  3. src/shared/runtime_eval.py — RAGAS scoring functions per agent (score_quant_response, score_rag_response, score_market_context_response, score_analytics_output, score_reviewer_output). Custom DomainSpecificRubrics for financial-specific metrics (citation_quality, risk_disclosure, etc.).
  4. pyproject.toml — pytest configuration, marker definitions, coverage settings.

What you learn: ~370 test cases across 40+ files. RAGAS runtime evaluation fires after every production query (deferred, LOW priority). Custom financial rubrics for domain-specific quality assessment (citation quality, risk disclosure, recommendation clarity, response completeness).

End-to-End Request Flow

Once you've read all 12 steps, the full flow for "Should I invest in NVDA?" looks like this:

User types query in Next.js frontend
  → CopilotKit POST /api/copilotkit → AG-UI SSE bridge
  → FinSightAgentExecutor.execute()

  1. GUARDRAILS: is_off_topic? ticker_valid? semantic_cache hit?
  2. MEMORY: TickerMemory.get_latest("NVDA") — today's brief? return immediately
  3. MEMORY CONTEXT: inject prior recommendation into prompt
  4. LLM DELEGATES (parallel — one assistant turn):
     a. send_message("Financial RAG Agent", "NVDA")
        → RAG Agent (LlamaIndex): ChromaDB retrieval + LLM summary
     b. send_message("Quant Analysis Agent", "NVDA")
        → Quant Agent (LangGraph): DAG pipeline with 8-group weighted voting
     c. send_message("Market Context Agent", "NVDA")
        → Market Context Agent (CrewAI): macro + peer narrative
     d. send_message("Analytics Agent", "NVDA")
        → Analytics Agent (PydanticAI): trend, forecast, charts, stats, anomaly
  5. REVIEW: send_message("Reviewer Agent", "NVDA")
     → Reviewer Agent (OpenAI Agents SDK): 6 deterministic checks + LLM synthesis
  6. LLM SYNTHESIZES all 5 outputs + review into BUY/HOLD/SELL
  7. AUTO-SAVE: TickerMemory, PortfolioStore, PerformanceTracker
  8. EVAL (deferred, LOW priority): RAGAS metrics → Langfuse
  → Response streamed back to frontend via SSE
