Agents Reference

Agent 1: Orchestrator (ADK)

PropertyValue
FrameworkGoogle ADK
Port8001
Agent CardBuilt programmatically in agent_1_adk/main.py
DiscoveryA2ACardResolver via /.well-known/agent-card.json, async 3x retry
A2A EndpointPOST /a2a

The orchestrator uses a single LlmAgent with one send_message tool:

  1. Discovers agents in background via SubAgentClient.discover() — async A2ACardResolver with retries
  2. Memory context injection — extracts ticker, retrieves latest recommendation, prepends to user message (~300 tokens)
  3. LLM routes to agents — calls send_message(agent_name, task). Parallel with qwen; sequential with other models.
  4. Synthesizes results — produces BUY/HOLD/SELL recommendation
  5. Auto-save — persists ticker brief, portfolio, and performance record to SQLite

Architecture

Module load → SubAgentClient.discover() in background task
  → A2ACardResolver(http, "http://localhost:8002")
  → A2ACardResolver(http, "http://localhost:8003")
  → A2ACardResolver(http, "http://localhost:8004")
  → self.agents populated → instruction updated

FinSightAgentExecutor:
  A2A Request → execute()
  → _build_memory_context(query) → inject prefix
  → RUNNER.run_async(user_query)
  → ADK LlmAgent (tools: [send_message, load_memory])
    → LLM decides which agents to call
    → send_message("Financial RAG Agent", "Analyze NVDA...")
    → send_message("Quant Analysis Agent", "Compute metrics...")
    → send_message("Sentiment Intelligence Agent", "Sentiment...")
    → LLM synthesizes BUY/HOLD/SELL
  → _add_events_to_memory() → persist session
  → _store_memory() → TickerMemory + PortfolioStore + PerformanceTracker

after_agent_callback (ADK web UI path):
  → callback_context.add_events_to_memory(events=..., custom_metadata={...})
  → SQLiteMemoryService.add_events_to_memory()

Streaming Event Flow

event 1: task { state: SUBMITTED }          ← skipped (non-terminal)
event 2: status_update { WORKING, msg }     ← skipped (non-terminal)
event 3: artifact_update { data: {...} }    ← returned (actual result)
    OR status_update { COMPLETED, msg }     ← returned (terminal text)
    OR task { state: COMPLETED, artifacts } ← returned (non-streaming fallback)

Agent 3: Quant (LangGraph)

PropertyValue
FrameworkLangChain + LangGraph

Data SourceMCP (get_prices, get_financials)
Port8003
A2A EndpointPOST /a2a

Skill

IDNameDescription
quant_analysisQuantitative AnalysisSharpe ratio, Beta, VaR, volatility, DCF valuation, stress tests

Architecture

Request → DefaultRequestHandler → GenericAgentExecutor(QuantAgent)
  → QuantAgent.stream(query, context_id, task_id)
    → extract_holdings(query, exclude_ticker=ticker) → ["AAPL", "MSFT", "GOOGL"]
    → QuantAgent.analyze(ticker, portfolio_holdings=holdings)
      [MCP: get_prices → parse Close data] → compute_metrics → branch
        → high_volatility (>35%) → stress_test, sets dcf_error
        → low_volatility (≤35%) → dcf_valuation
      → portfolio_correlation
      → format_output (dcf_error in reasoning) → llm_summary
  → Yields: data response

Portfolio Holdings Extraction: extract_holdings() uses regex patterns to extract holdings from natural language. The orchestrator LLM is instructed to include holdings in the task text for the Quant agent.
