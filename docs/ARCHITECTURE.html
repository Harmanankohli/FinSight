Architecture

Overview

FinSight is a multi-agent investment research system where four specialized agents communicate via the Google A2A Protocol. The orchestrator (ADK LlmAgent) discovers sub-agents at startup via A2ACardResolver, delegates tasks via a single send_message tool, and the LLM routes to each agent. Each sub-agent processes tasks internally using its own framework and tools.

└──────────────────────────────────────────────────────────────┘

Orchestrator Architecture

The orchestrator (agent_1_adk/) uses a single LlmAgent with one send_message tool:

Module load → SubAgentClient.discover()
  → A2ACardResolver per seed URL
  → Returns typed AgentCard (protobuf)
  → self.agents populated → instruction updated

A2A Request → FinSightAgentExecutor.execute()
  → RUNNER.run_async(user_query)
  → LlmAgent (no pre-fetch)
    → LLM calls send_message(agent_name, task)
    → SubAgentClient → A2A task to sub-agent
    → SubAgentClient → A2A response
    → LLM calls next agent
    → LLM synthesizes BUY/HOLD/SELL
  → COMPLETED with synthesis

Key Design Choices

  • A2ACardResolver for discovery — standard A2A well-known endpoint, protobuf AgentCard types
  • ClientFactory for A2A communication — matches official A2A SDK pattern
  • Single send_message tool — not one tool per agent; LLM passes agent name as parameter
  • Streaming event handling — correctly skips SUBMITTED/WORKING, captures artifact_update and terminal events
  • Background async discovery — supports both ADK Web UI (running event loop) and CLI entrypoints
  • WindowsSelectorEventLoopPolicy — prevents ConnectionResetError on Windows
  • Programmatic AgentCards — built in code using protobuf types instead of static JSON

GenericAgentExecutor Pattern

All sub-agents extend BaseAgent and implement stream(). A shared GenericAgentExecutor handles A2A lifecycle:

A2A Request → DefaultRequestHandler → GenericAgentExecutor.execute()
  → BaseAgent.stream(query, context_id, task_id)
  → Yields: {response_type, content, is_task_complete, require_user_input}
  → GenericAgentExecutor converts to events
  → COMPLETED state

Agent Architectures

RAG Agent (LlamaIndex)

A2A Request → DefaultRequestHandler → GenericAgentExecutor(RAGAgent)
  → RAGAgent.stream()
    → _ensure_ingested(ticker)
      → MCP: get_company_filings(ticker)
      → MCP: get_filing_content(edgar_url, ix_url) for each filing
      → DocumentIngestionPipeline.ingest_sec_filings_batch() → ChromaDB
    → FinancialIndexManager.query(ticker, query)
      → Try: RouterQueryEngine
      → Fallback: SEC filings index directly
  → Yields data response with summary + sources

Content Ingestion: Fetches actual SEC filing content via get_filing_content(), extracting text from raw EDGAR URLs with fallback to IXBRL viewer URLs.

Quant Agent (LangGraph)

A2A Request → DefaultRequestHandler → GenericAgentExecutor(QuantAgent)
  → QuantAgent.stream()
    → extract_holdings(query) → portfolio_holdings list
    → analyze(ticker, portfolio_holdings=holdings)
      [MCP: get_prices → parse Close data]
      → compute_metrics → conditional branch:
          high volatility (>35%) → stress_test, dcf_error set
          low volatility  (≤35%) → dcf_valuation [MCP: get_financials]
      → portfolio_correlation
      → format_output → llm_summary
  → Yields data response with dcf_error in result

Correlation only on explicit request: The orchestrator prompt instructs the LLM to include holdings in the quant agent task only when the user explicitly mentions portfolio holdings or asks for correlation in their current message. Memory context portfolio lines are labelled as background reference so they do not auto-trigger correlation for single-ticker queries.

Sentiment Agent (CrewAI)

A2A Request → DefaultRequestHandler → GenericAgentExecutor(SentimentAgent)
  → SentimentAgent.stream()
    → Parallel MCP data collection (asyncio.gather):
      → get_news_sentiment
      → get_company_filings
    → 2-agent CrewAI: Analysis → Synthesis
  → Yields data response

Observability & Tracing

Langfuse provides distributed tracing across all four agent processes. Trace context is propagated through A2A via text-based injection:

Orchestrator
  → langfuse.trace(name="finsight-query")
  → get_current_trace_id() + get_current_observation_id()
  → inject_trace_context(task, trace_id, parent_span_id)

Sub-agents
  → extract_trace_ids(query) → (trace_id, parent_span_id, clean_query)
  → start_observation(trace_context=...)
  → Langfuse joins the span to the orchestrator's trace tree

Span Noise Filtering

Uses is_default_export_span to filter out noisy A2A internal spans and HTTPX transport spans. Only high-level workflow spans and LLM spans are exported.

Memory Context Injection

Before each query, the executor injects memory context into the user message:

User Query → Executor._inject_memory_context(query)
  → extract_ticker(query) → "NVDA"
  → TickerMemory.get_latest("NVDA") → last recommendation
  → PortfolioStore.get() → current holdings (background reference label)
  → Prepend: [MEMORY CONTEXT] ... [/MEMORY CONTEXT]

Portfolio holdings in memory context are labelled as background reference. The orchestrator LLM is instructed not to forward them to sub-agents unless the user explicitly requests portfolio analysis in their current message.

Auto-Save Flow

After each successful response, the executor automatically persists to TickerMemory, PortfolioStore, and PerformanceTracker. No LLM tool call required.

File Logging

All services write structured logs to the logs/ directory via shared/logging_config.py:

from shared.logging_config import setup_file_logging
setup_file_logging("orchestrator")  # → logs/orchestrator.log

setup_file_logging(service_name) attaches a RotatingFileHandler (10 MB, 5 backups) and a StreamHandler to the root logger at module level in each server entry point. Duplicate handler registration is guarded.
