FinSight Improvements

Caching, guardrails, RAGAS evaluation, observability, and deployment hardening

This document describes the complete improvement plan implemented across six tiers: TTL caching, RAG performance, input/output guardrails, RAGAS evaluation pipeline, observability completions, and deployment.

Tier 1 — Caching

1A. TTL Tool-Result Cache (MCP Server)

Added a thread-safe _TTLCache class (no new dependencies) wrapping all high-cost MCP tools:

ToolTTLCache KeyRationale
get_prices5 min(ticker, period, interval)Intraday stable
get_financials24 h(ticker,)Quarterly data — stable within a day
get_news_sentiment15 min(ticker, limit)Fast-moving but not per-second
get_filing_contentpermanent LRU-200edgar_urlFilings are immutable
_fetch_submissions6 hcikEDGAR submission JSON rarely changes intraday

Expected speedup Second identical query: ~8s → <200ms for cached tools.

1B. LangChain SQLiteCache

Activated SQLiteCache in agent_3_langgraph/nodes.py at module load time. The llm_summary_node is the only LangChain LLM call in the quant graph; identical ticker+metrics inputs now reuse the cached response from .langchain_cache.db.

1C. KV Cache Prompt Prefix Optimization

Extracted the static PROCEDURE block from _build_instruction() in agent_1_adk/agent.py into a module-level constant _STATIC_PREAMBLE. The dynamic tail (today's date + agent list) is now the only part that changes between calls. LM Studio's KV cache keyed on the token prefix can now reuse ~85% of the prompt tokens on repeated queries.

Same pattern applied to backstory strings in agent_4_crewai/crew.py.

1D. Semantic Cache for Investment Queries

New module shared/semantic_cache.py uses the already-running ChromaDB instance and all-MiniLM-L6-v2 embedder. On a cache miss, the query is stored with its response. On a hit (cosine similarity ≥ 0.95), the cached response is returned without invoking any agent. TTL: 1 hour. Controlled by SEMANTIC_CACHE_ENABLED=true environment variable (off by default).

Threshold tuning: start conservative at 0.95. "Analyze NVDA" and "Analyze Nvidia" will hit (similarity ~0.97); "Analyze NVDA bullish case" and "Analyze NVDA bearish risks" will miss (similarity ~0.88). Tune down to 0.92 after monitoring hit rate vs. precision in production.

Tier 2 — RAG & Memory Performance

2A. Embedding Model Pre-Warm

Added an on_startup hook to agent_2_llamaindex/server.py that initializes FinancialIndexManager in a background thread executor. The embedding model (all-MiniLM-L6-v2) and ChromaDB connection are ready before the first request arrives, eliminating the 3–8s cold-start penalty.

2B. Incremental RAG Ingestion

Added ingested_filings (edgar_url PK, ticker, ingested_at) table to shared/memory/store.py. In agent_2_llamaindex/executor.py, _ensure_ingested() now checks this table before fetching and embedding each filing. Already-ingested URLs are skipped, reducing repeat ingest time for the same ticker from ~30s to ~1s.

Tier 3 — Guardrails

3A. Input Guardrails

Two guards added at the top of FinSightAgentExecutor.execute():

  1. Off-topic filter — regex matching weather, recipes, sports, movies, etc. Returns a canned "investment-only" message in <100ms without touching the orchestrator.
  2. Invalid ticker pre-check — if a ticker is extracted from the query, calls validate_ticker via MCP before spawning any sub-agents. Returns a clean error in <2s for unknown tickers instead of letting all 3 agents fail after 30s+ each.

3B. Output Guardrails

Two guards added in _process_response():

  1. Short response guard — responses <50 characters are rejected with TASK_STATE_FAILED.
  2. Signal check — if the response lacks a BUY/HOLD/SELL signal and a ticker was present in the query, a Langfuse warning observation is emitted for monitoring.

4E. Automated Financial Outcome Evaluation

PerformanceTracker.record_recommendation() now fetches the live price via yfinance at record time, so price_at_rec is always populated. After each save_brief() call, a background task invokes evaluate_all() to populate realized_return for any recommendations where the price was recorded.

Tier 5 — Observability Completions

5A. LangGraph Instrumentation

Added LangChainInstrumentor().instrument() to agent_3_langgraph/server.py. LLM calls in llm_summary_node now appear as spans in Langfuse under the quant agent traces. Previously only Starlette HTTP spans were captured for this agent.

5B. Sub-Agent Latency Tracking

Each SubAgentClient.send_message() call now emits a Langfuse span with latency_ms and agent metadata. This enables per-agent latency breakdown in the Langfuse dashboard without modifying any agent implementations.

5C. Config Validation

Added shared.config.validate() that raises EnvironmentError if required vars are missing or have placeholder values. Logs a warning (not an error) when LANGFUSE_PUBLIC_KEY is the default placeholder, since local dev often skips Langfuse.

Tier 6 — Deployment

Health Check Endpoints

All five services now expose GET /health returning {"status": "ok", "agent": "<name>"}. The MCP server health endpoint is mounted alongside the FastMCP SSE app via a Starlette router wrapper.

docker-compose.yml Updates

  • All services have healthcheck configurations using curl -f /health
  • All depends_on entries use condition: service_healthy
  • finsight_memory named volume mounted to agent-adk
  • SEMANTIC_CACHE_ENABLED=false env var added to agent-adk (opt-in)

Orchestrator Dockerfile

Created agent_1_adk/Dockerfile so all 5 services are now containerized. Follows the same Python 3.12-slim pattern as the other agent Dockerfiles.
