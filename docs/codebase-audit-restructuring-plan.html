Part 2: Code Issues

P0 Critical — Fix Immediately

1. DCF Terminal Value Formula Bug

quant/nodes/dcf.py:130

Issue: Terminal value (line 130) uses latest_fcf * (1 + growth_rate) ** 5 — compounding the initial high growth rate for all 5 years. But the FCF projection loop (lines 121–128) already tapers yr_growth toward terminal_growth in years 3-5. The terminal value should use the tapered year-5 FCF, not straight-line high-growth compounding. This double-counts high growth and inflates intrinsic value for growth stocks.

Fix: Track the year-5 projected FCF from the loop and use it: terminal_value = (projected_fcf_year5 * (1 + terminal_growth)) / (wacc - terminal_growth). Specifically, accumulate projected_fcf across loop iterations and use the final value (year=5) rather than recomputing with (1 + growth_rate) ** 5.

Behavioral constraint: This changes DCF output values. Verify by comparing before/after for a known growth stock (e.g., NVDA) and a mature stock (e.g., KO). The mature stock's output should change minimally. Update any golden test fixtures in src/tests/characterization/test_quant_nodes_io.py (dcf_valuation_node test at line ~169).

2. Access Token Cookie Without HttpOnly — XSS Vulnerability

web/nextjs-app/lib/auth.ts:18–19

Issue: setTokenCookie sets document.cookie without HttpOnly. Access token readable by JavaScript, vulnerable to XSS exfiltration.

Fix: Remove client-side cookie. Use only in-memory React state. If cookie needed for SSR, set HttpOnly and Secure flags server-side.

3. Fallback Password Hasher Stores Plaintext

shared/memory/user_store.py:23–33

Issue: _FallbackHasher stores plain:{password} when argon2 not installed. Dangerous if deployed without argon2.

Fix: Make argon2 a hard dependency. Remove the fallback hasher entirely.

Note: argon2-cffi is already in main dependencies (pyproject.toml line 62). The fallback is dead code in normal installs but remains a risk if someone installs without the dependency. Verify CI installs it (ci.yml line 58 installs argon2-cffi explicitly).

pyproject.toml:244–254

Issue: strict = true set but ignore_errors = true applied to ALL production modules. mypy is effectively off.

Fix: Remove ignore_errors overrides. Fix type errors incrementally.

P1 High — Fix Soon

5. Portfolio Store Uses session_id as user_id NEW

shared/memory/portfolio_store.py:57–58, 75–76, 83–85

Issue: upsert_from_context queries/inserts user_profiles using ctx.session_id as user_id. Each session creates a separate portfolio profile — a user analyzing the same stock across two sessions gets disconnected portfolios.

Fix: Use ctx.user_id (authenticated user ID) instead of ctx.session_id.

Behavioral constraint: When AUTH_ENABLED=false, there is no authenticated user_id. Ensure fallback to session_id when auth is disabled (preserve anonymous user behavior). Existing portfolio data keyed by session_id will become orphaned — consider a migration or accept data loss for pre-auth profiles.

6. Sessions List Allows user_id from Query Params (Auth Bypass) NEW

orchestrator/api_routes.py:131

Issue: user_id = _user_id(request) or request.query_params.get("user_id") — when auth is enabled and _user_id returns None, the fallback reads user_id from query params. An unauthenticated user could pass ?user_id=admin and see that user's sessions.

Fix: Only fall back to query params when auth is disabled. When auth is enabled, reject requests where _user_id returns None.

7. Report Authorization Bypass for user_id=None NEW

orchestrator/api_routes.py:233–254

Issue: report_by_id() SQL: WHERE id = ? AND (user_id = ? OR ? IS NULL). When _user_id(request) returns None, the IS NULL clause is always True — any user can access any report.

Fix: When auth is enabled, reject requests where _user_id returns None.

8. CrewAI asyncio.run() Inside Async Context

market_context/mcp_tools.py:55–61

Issue: asyncio.run(self._mcp.call_by_name(...)) creates new event loop inside running async context. Raises RuntimeError.

Fix: Use nest_asyncio or restructure to synchronous MCP client.

9. CrewAI crew.kickoff() Blocks Event Loop

market_context/crew.py:114–115

Issue: Sync blocking kickoff() in async def analyze() starves other coroutines.

Fix: Wrap in loop.run_in_executor(None, crew.kickoff).

10. HuggingFace Download Blocks Event Loop

financial_rag/index_manager.py:135 (in __init__)

Issue: HuggingFaceEmbedding(model_name=...) on line 135 triggers a sync download of ~130MB on first run, blocking the event loop during FinancialIndexManager.__init__().

Fix: Move to run_in_executor or lazy-load on first query.

Note: The RAG server already has a prewarm path (_do_prewarm() in server.py) that runs in a thread executor. The __init__ itself is called synchronously within prewarm. HF_HUB_OFFLINE=1 is set by default in bootstrap — the download only happens if models aren't cached locally. Prewarm mitigates this at startup, but any code path that constructs FinancialIndexManager() outside prewarm will still block.
