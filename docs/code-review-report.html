Overall Assessment

The codebase demonstrates strong production engineering. The layered caching architecture (L1 TTLCache + L2 Redis), circuit breaker pattern in the eval pipeline, deferred eval gate for LLM scheduling, and defense-in-depth sandboxing are all well-executed. The main concerns are event-loop binding issues, migration error handling, and a few config duplication paths.

Verdict: The blocking issues (#2 and #3) should be fixed before any production deployment under concurrent load. The remaining items are quality improvements that reduce long-term maintenance burden.

Blocking Issues

1. Dict mutation during GC scan

shared/runtime_eval.py:84

for k in [k for k, ts in _dedup_cache.items() if now - ts > _DEDUP_TTL]:
    _dedup_cache.pop(k, None)

The list comprehension materializes all keys even when the cache is small. More critically, this full-dict scan runs on every _dedup_seen() call. When the cache exceeds 256 entries, this becomes an O(n) operation on the hot path of every eval gate check.

Suggestion: Use lazy expiry (check on read, not bulk-scan), or bound the scan to at most N entries per call to amortize cost.

2. Module-level asyncio.Lock() binds to wrong event loop

shared/mcp_client.py:39

_client_lock = asyncio.Lock()

This lock is created at import time and bound to whichever event loop happens to be running then. In test setups or multi-loop configurations, this will raise RuntimeError or silently bind to the wrong loop. The lock should be created lazily inside get_shared_mcp().

Fix: Move _client_lock = None to module level, create it inside get_shared_mcp() with asyncio.get_running_loop().

3. Deprecated asyncio.get_event_loop()

shared/eval_gate.py:43

loop = asyncio.get_event_loop()

Deprecated since Python 3.10. Raises DeprecationWarning and may fail in Python 3.12+ when no loop is running. Should use asyncio.get_running_loop().

Fix: Replace with loop = asyncio.get_running_loop().

Important Issues

4. Fire-and-forget Redis writes swallow errors

shared/redis_cache.py:113

asyncio.create_task(self._redis_set(key, value))

If _redis_set raises, the exception is silently lost (only logged at debug level). For critical cache writes, consider adding an exception handler on the task or using asyncio.shield().

5. Semantic cache timestamp default is semantically ambiguous

shared/semantic_cache.py:97

if time.time() - float(meta.get("ts", 0)) < self._ttl:

A missing ts defaults to epoch 0, which always evaluates to "expired." This is correct behavior but the intent is unclear. An explicit if meta.get("ts") is None: return None guard would be more readable and prevent surprises if the default ever changes.

6. Hardcoded ticker lookup table is a maintenance burden

shared/report_generator.py:207-235

_TICKER_NAMES: dict[str, tuple[str, str, str]] = {
    "AAPL": ("Apple Inc.", "Technology", "NASDAQ"),
    ...
}

New IPOs, sector reclassifications, or delistings require code changes. Consider fetching from yfinance/MCP at runtime, or at minimum externalizing to a config file.

7. DB migrations swallow all exceptions

shared/memory/store.py:149-161

try:
    await conn.execute("ALTER TABLE memory_entries ADD COLUMN search_text ...")
    await conn.commit()
except Exception:
    pass

Catching Exception masks real failures (disk full, corruption, permission errors). Should catch sqlite3.OperationalError specifically — that's what "column already exists" raises.

8. Duplicated embedding model config

shared/memory/memory_service.py:34

EMBEDDING_MODEL = "all-MiniLM-L6-v2"

This duplicates shared.config.EMBED_MODEL. If someone changes the config, the memory service will use a different model than the semantic cache, causing embedding mismatch and silent search degradation. Should import from config.

Suggestions

9. Token bucket busy-wait can cause excessive wakeups

shared/rate_limiter.py:30

await asyncio.sleep(deficit / self.rate)

When deficit is very small (microseconds), this causes tight-loop wakeups. Consider a minimum sleep floor of ~10ms.

10. Type annotation uses lowercase any

shared/base_agent.py:26

async def stream(...) -> AsyncIterable[dict[str, any]]:

Should be dict[str, Any] from typing. Lowercase any is the builtin function, not a type. Type checkers won't flag this but it's incorrect.

11. Repeated local import logging inside function

shared/config.py:114-124

if LANGFUSE_PUBLIC_KEY in ("pk-lf-...", "", None):
    import logging
    logging.getLogger(__name__).warning(...)

The logging import should be at module level. Repeated local imports are a micro-optimization anti-pattern that adds noise.

12. Reaching into SDK private internals

shared/a2a_store.py:58

owner_tasks = self._mem._impl.tasks.setdefault(owner, {})

This couples to InMemoryTaskStore private implementation. If the SDK updates its internals, this breaks silently. Consider using the public API or pinning the SDK version.

13. Double get_db() call is misleading

shared/memory/portfolio_store.py:47-59

The function acquires a connection on line 47, uses it for a SELECT, then acquires a new connection inside the write lock on line 59. Since get_db() returns a singleton this is functionally fine, but the pattern looks like two different connections and could confuse readers.

14. query.upper() destroys case before regex

shared/ticker_utils.py:55

query = query.upper()

Upper-casing the entire query before regex matching means company names like "Visa" become "VISA", which could affect the mixed-case regex on line 63 that relies on [A-Z][a-z] patterns.

Highlights — What's Working Well

✅ Layered caching with graceful degradation

The L1 TTLCache + L2 Redis architecture in redis_cache.py is well-designed. Redis failures silently fall back to in-process cache without restart. The single-flight dedup in TTLCache prevents thundering herd.

✅ Circuit breaker prevents cascading failures

The eval pipeline in runtime_eval.py correctly opens the circuit after 5 consecutive RAGAS failures, disabling eval for the process lifetime. Combined with burst limiting and dedup, this prevents eval scoring from destabilizing production inference.

✅ Deferred eval gate sequences inference correctly

eval_gate.py holds sub-agent evals until the orchestrator releases them, preventing eval LLM calls from starving the synthesis phase. The 120s auto-release safety net is a nice touch.

✅ Hybrid search with RRF fusion

The memory service's BM25 + sentence-transformer embedding search, fused via Reciprocal Rank Fusion, provides robust retrieval that handles both keyword and semantic queries well.

✅ SQLite WAL + foreign keys + busy timeout

The database layer in store.py shows production-grade SQLite hygiene: WAL mode for concurrent reads, foreign keys enforced, 5s busy timeout for write contention, and idempotent schema migrations.

✅ Defense-in-depth sandbox

sandbox.py implements three security layers: AST-level static analysis, subprocess isolation, and OS-level resource limits (CPU, memory, file descriptors). The restricted builtins whitelist in the child process is a strong secondary defense.

Recommended Priority

  1. Fix #2 and #3 (event loop binding) — These will cause hard-to-debug failures under concurrent load in production.
  2. Fix #7 (migration error handling) — Broad exception swallowing can mask real DB issues in production.
  3. Fix #8 (config duplication) — Silent embedding model mismatch causes gradual search quality degradation.
  4. Address #1, #4, #5 — Performance and reliability improvements on hot paths.
  5. Remaining suggestions — Code quality improvements, low urgency.
