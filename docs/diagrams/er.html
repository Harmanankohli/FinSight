Key Relationships

  • sessions → events: One session has many events. Each event is a single turn (user message, agent response, tool call). The content JSON column stores the full event payload.
  • sessions → memory_entries: FTS5-indexed plain text for cross-session load_memory search. content_hash prevents duplicates.
  • sessions → agent_output_store: Cross-process bridge. Orchestrator writes sub-agent outputs; reviewer reads by session_id. 600s TTL.
  • ticker_briefs: Independent table keyed by ticker + analysis_date. Each row is a complete BUY/HOLD/SELL analysis with full synthesis text.
  • recommendation_records: Same recommendation with price_at_rec snapshot. Updated asynchronously by PerformanceTracker when evaluation completes.
  • ingested_filings: Dedup for RAG ingestion. edgar_url is the canonical primary key (SEC URLs are immutable).
